# 外部連携の読み方

## 探す場所

| 形 | 手がかり |
| --- | --- |
| 送信（HTTP） | `fetch` / `axios` / `http.Client` の呼び出し。URL がリテラルか環境変数か |
| 送信（SDK） | `import` している外部サービスの SDK |
| 受信（Webhook） | ルート定義のうち `webhook` `callback` `notify` を含むパス |
| 受信（キュー） | メッセージ消費のハンドラ |
| 設定だけ | `.env.example` の変数名。対応する呼び出しが無いものに注意 |

`inventory.py` の `integration` 候補が起点。ただし**候補に挙がらない場所にもある。**
`.env.example` の変数名から逆に辿るのが確実。

## 方向で分ける

章を送信と受信で分ける。連携先ごとにまとめると、Webhook と API 呼び出しが混ざり、
障害の切り分けに使えなくなる。

## 送信で取るもの

- 連携先 / 呼ぶもの（API 名・メソッド名）/ 呼ばれる場所（機能名）/ 関連テーブル
- **送信する項目** — 型・必須つき
- **受け取る項目** — こちらが使うものだけ

SDK 経由でリクエストの構造が読めない場合は「SDK 内部・未確認」と書く。
無理に推測しない。

## 受信で取るもの

- 受け口（メソッドとパス）/ 送り主 / 検証方式 / 更新するテーブル
- **受け取る項目** — 型つき
- **返す応答** — Status と発生条件

## 取らないもの

タイミング・タイムアウト・リトライの設定値・失敗時に内部でどう復旧するか・
冪等性の仕組み・署名検証の実装・イベントごとの処理内容・実装ファイルのパス。

判断の基準は「**やり取りする内容か、その処理か**」。IF は書く、処理は書かない。

## 認証情報

**値を書かない。** 環境変数名だけ。設定場所が読み取れる場合だけ足す。
**読み出し箇所のファイルパスは書かない。**
URL も、秘匿部分を含むものは書かない。

`.env` / `.env.local` / `.env.production` のような**実ファイルは開かない。**
読んでよいのは `.env.example` などのテンプレートだけで、そこでも**変数名しか見ない。**
値が書き込まれていても読まないし、資料にも書かない。

資料を書いたらその場で `scripts/secrets.py` を通す。検出が出たら人間に判断を回す。

## 判定できないとき

- 設定だけあって呼び出しが無い → 一覧に載せて未確認。**「使われていない」と断定しない**
- 連携先が読めない → 一覧に載せて未確認
