# 書き方

全資料に共通する規則。`templates/` と矛盾したら `templates/` が勝つ。

## 必ず守ること

- 言語は日本語
- 見出しは `###` まで
- 図は Mermaid。ASCII 箱型図は日本語混じりで文字幅が揃わず崩れるので使わない
- 相対パス・ファイル名はインラインコードで書く。裸で書くと自動リンク化される
- 判定できなかったものは「未確認」と書き、末尾の未確認一覧へ送る。**「調べた範囲」も書く**
- 冒頭に生成時点のコミットハッシュを記録する（将来の差分更新の前提）

## Markdown として書く

- **HTML タグを書かない。** `<span class="...">` のような記法を混ぜない。
  「未確認」は `**未確認**` のように Markdown の強調で書く。
  HTML を混ぜると Notion への変換でも、md のまま読むときも壊れる
- **日本語の 1 文字を取り違えない。** 生成中に別の文字（同じ見た目の別字・別言語の文字）が
  混ざる事故が実際に起きる。書いたあと、見慣れない文字が無いか確認する
- 表のヘッダーに使う語を、本文のセルで安易に使わない。
  「テーブル」を含むセルが本文にあると、機械が表のヘッダーと誤認することがある

## 書かないこと

- **推測で埋めた仕様。** 書く価値があると判断した場合のみ「推測」と明示し、根拠にした箇所を併記する
- 検討の経緯や却下案のうち、docs にもコードコメントにも記録が無いもの。ないものを創作しない
- **機密。** 環境変数は名前と所在まで。以下は資料に書かない。
  - 値・トークン・API キー・パスワード・接続文字列
  - 私有 IP アドレス（`10.` / `192.168.` / `172.16-31.`）と内部ホスト名（`*.internal` `*.local` `*.corp`）
  - 実在する個人のメールアドレス・電話番号
  - 秘匿部分を含む URL（クエリにトークンが乗っているものなど）
- 「使われていない」「不要」の断定。参照が見つからないことは、存在しないことの証明にならない

## 表の書き方

- 列数は読みやすさ優先。Notion への変換は別スキルの仕事なので、ここで列を削らない
- セルに「—」を入れて空欄を作らない。該当なしは「—」、判定できないは「未確認」と書き分ける
- セルに収まらない説明は**書かない**。この資料は俯瞰用で、実装の挙動は対象外

## 図の書き方

- 1 枚に詰め込まない。ノードが 12 を超えたら分ける
- 矢印には必ずラベルを付ける。ラベルの無い矢印は「関係がある」しか意味しない
- 条件付き・エラー系は破線にして、正常系の流れを追えるようにする

## 何を書き、何を書かないか

**外部から観測できることは書く。内部での実現方法は書かない。**

| 書く（外から見える） | 書かない（中の話） |
| --- | --- |
| 入力と出力の形（項目・型・必須・制約） | 処理の順序・呼び出しの流れ |
| ステータスコードと、それが返る条件 | どの関数のどの分岐で判定しているか |
| 画面の表示条件・活性条件・エラー表示 | 状態管理の仕組み・Component 構成 |
| 宣言された構造（カラム・制約・Index・トリガの存在） | トリガ本体の処理・RLS の内容 |
| 遷移の条件（未ログインならログイン画面へ） | 遷移を実装しているガードの中身 |

**「失敗したときにどうなるか」は分けて考える。** 呼び出す側・利用者に見える結果
（409 が返る、エラーが表示される、前の画面へ戻る）は**書く**。
内部でどう復旧するか（再送する、ロールバックする、書き戻す）は**書かない**。

## 分量

**目的は「全体の構造と内容が理解できること」。** それを超えた作り込みはしない。

- **空のブロックを書かない。** 「Path Parameter — なし」「Header — 共通のみ」のような
  見出しだけの行を残さず、該当が無ければ**表ごと省く**
- **同じ形のものは繰り返さない。** 「`/api/moves` と同じ形。Query は `name` と `q`」で済ませる
- **例を載せない。** リクエスト / レスポンスの JSON 例は、フィールド表があれば不要
- **表の列を増やさない。** NULL 可否のような情報は説明欄に 1 語で書く
- 説明は**1 行**。2 文以上になったら削る余地がある

**迷ったら書かない。** 書きすぎた資料は読まれず、実装とずれた説明は害になる。
**依頼されていない章を足さない。** 実装ファイルのパスは書かない。

## 未確認一覧の書き方

| 対象 | 分からなかったこと | 調べた範囲 |

「調べた範囲」を書く理由は、次に読む人が同じ調査を繰り返さないため。
「API・バッチ・管理画面を全文検索したが代入箇所なし」のように、
**どこまで探したかを具体的に書く。**
