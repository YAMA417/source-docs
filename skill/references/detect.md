# スタック判定

`inventory.py` の判定は依存名の一致だけで行う。**判定結果を鵜呑みにしない。**

## 手順

1. `python3 scripts/inventory.py --repo <path>` を実行し、frontend / backend / orm / db を見る
2. 「判定できず」が出た区分は、manifest を直接開いて依存を読む
3. モノレポならワークスペースごとに区分が違う。リポジトリ単位ではなくパッケージ単位で判定する。
   `--repo` を複数渡すか、ワークスペースのパスを個別に渡す
4. `references/stacks/` に該当するファイルがあれば読む。無ければ汎用手順で進む

## 判定の材料

| 見るもの | そこから分かること |
| --- | --- |
| manifest の依存名 | フレームワーク・ORM・DB ドライバ |
| 設定ファイル（`next.config.*` `nest-cli.json` `strapi` の構成 など） | フレームワークの確証 |
| ディレクトリ構造 | ルーティングの方式（ファイルベースか定義ベースか） |
| CI 設定・Dockerfile | 実行環境、DB の種類 |
| `.env.example` | 外部連携の存在（値は読まない、名前だけ） |

## 判定できないときにやること

**判定を諦めて汎用手順で進む。推測でフレームワーク名を書かない。**
ゲート 1 で「この区分は判定できなかった」と人間に伝える。

汎用手順で読み取れなかった書き方があれば、検証のあとに
`references/stacks/<name>.md` へ「何が見つけにくいか」「どこを見れば分かるか」を書き足す。
